# ข้อเสนอโครงการสหกิจศึกษา

สถานะเอกสาร: ร่างสำหรับพิจารณาขอบเขตและหารือกับสถานประกอบการ

## 1. ชื่อโครงการ

**ภาษาไทย:** การพัฒนาระบบแนะนำสถานที่ท่องเที่ยวเฉพาะบุคคลด้วยการเรียนรู้ของเครื่อง

**ภาษาอังกฤษ:** Development of a Personalized Tourist Attraction Recommendation System Using Machine Learning

## 2. หลักการและเหตุผล

สถานที่ท่องเที่ยวมีความหลากหลายทั้งด้านพื้นที่ ประเภทสถานที่ และกิจกรรม ผู้ใช้แต่ละคนมีความสนใจแตกต่างกัน การแสดงรายการสถานที่แบบเดียวกันให้ผู้ใช้ทุกคนจึงอาจไม่ช่วยให้ผู้ใช้ค้นพบสถานที่ที่ตรงกับความต้องการ การพัฒนาระบบที่นำข้อมูลความสนใจของผู้ใช้มาประกอบการแนะนำสถานที่จึงเป็นแนวทางหนึ่งในการช่วยจัดลำดับข้อมูลและสนับสนุนการตัดสินใจท่องเที่ยว

โครงการนี้มีชุดข้อมูลสถานที่ท่องเที่ยวจำนวน 2,994 รายการ ครอบคลุมภาคเหนือและภาคใต้รวม 31 จังหวัด ข้อมูลประกอบด้วยชื่อสถานที่ คำอธิบาย จังหวัด ภูมิภาค หมวดหมู่ ประเภทสถานที่ กิจกรรม ที่ตั้ง พิกัด และข้อมูลสื่อประกอบตามที่มีในแต่ละรายการ ข้อมูลดังกล่าวสามารถนำมาเตรียมเป็นคุณลักษณะสำหรับระบบแนะนำได้ โดยต้องตรวจสอบความครบถ้วน ความซ้ำซ้อน และความสอดคล้องของข้อมูลก่อนใช้งาน

ในระยะเริ่มต้นยังไม่มีชุดข้อมูลคะแนนความชอบหรือประวัติการเลือกสถานที่ของผู้ใช้ โครงการจึงเสนอให้พัฒนาระบบแนะนำจากคุณลักษณะสถานที่และความสนใจที่ผู้ใช้ระบุเป็นจุดเริ่มต้น พร้อมเก็บคะแนนความสนใจจากผู้ทดลองใช้เพื่อสร้างชุดข้อมูลสำหรับฝึกโมเดลที่เรียนรู้ความสัมพันธ์ระหว่างผู้ใช้กับสถานที่ จากนั้นเปรียบเทียบวิธีแนะนำและเลือกแนวทางที่เหมาะกับข้อมูลและข้อจำกัดของโครงการ

งานด้านการเรียนรู้ของเครื่องจะครอบคลุมการเตรียมข้อมูล การสร้างคุณลักษณะ การฝึกโมเดล การปรับค่าพารามิเตอร์ การประเมินผล และการเชื่อมโมเดลเข้ากับแอปพลิเคชัน โดยใช้ผลทดลองเป็นหลักในการตัดสินใจเลือกโมเดล

## 3. วัตถุประสงค์

1. พัฒนาระบบแนะนำสถานที่ท่องเที่ยวตามความสนใจและข้อมูลที่ผู้ใช้ระบุ
2. จัดเตรียมชุดข้อมูลสถานที่และเก็บข้อมูลความสนใจจากผู้ทดลองใช้สำหรับการพัฒนาโมเดล
3. ฝึกและเปรียบเทียบโมเดลการเรียนรู้ของเครื่องกับวิธีแนะนำพื้นฐานภายใต้เงื่อนไขการทดลองเดียวกัน
4. เชื่อมต่อโมเดลกับแอปพลิเคชันและฐานข้อมูลเพื่อให้ผู้ใช้ได้รับรายการสถานที่ที่จัดลำดับตามความเหมาะสม
5. ประเมินคุณภาพการแนะนำ ประสิทธิภาพการตอบสนอง และความพึงพอใจในการใช้งาน

## 4. ขอบเขตโครงการ

### 4.1 ข้อมูลสถานที่ท่องเที่ยว

- ใช้ชุดข้อมูลตั้งต้นจำนวน 2,994 รายการในภาคเหนือและภาคใต้รวม 31 จังหวัด
- ใช้ข้อมูลชื่อ คำอธิบาย หมวดหมู่ ประเภทสถานที่ กิจกรรม จังหวัด และภูมิภาคเป็นข้อมูลหลักสำหรับสร้างคุณลักษณะ
- ใช้ที่ตั้ง พิกัด รูปภาพ และข้อมูลสื่อประกอบสำหรับแสดงรายละเอียดตามความพร้อมของแต่ละรายการ
- ตรวจสอบข้อมูลซ้ำ ค่าว่าง และค่าที่ไม่สอดคล้องกันก่อนสร้างชุดข้อมูลใช้งาน จำนวนรายการหลังตรวจสอบอาจเปลี่ยนแปลง
- ตรวจสอบและระบุแหล่งที่มาและเงื่อนไขการใช้ชุดข้อมูลในรายงานฉบับสมบูรณ์

### 4.2 ข้อมูลผู้ใช้

- รับข้อมูลความสนใจด้านประเภทสถานที่ กิจกรรม และพื้นที่ท่องเที่ยวที่ต้องการ
- พิจารณารับข้อมูลส่วนบุคคลเพิ่มเติม เช่น ช่วงอายุ โดยกำหนดรายการข้อมูลร่วมกับสถานประกอบการก่อนพัฒนาแบบฟอร์ม
- เก็บเฉพาะข้อมูลที่จำเป็นต่อการทดลองและแจ้งวัตถุประสงค์แก่ผู้ทดลองใช้
- ใช้รหัสผู้ทดลองใช้แทนชื่อในชุดข้อมูลฝึกและประเมินโมเดล
- ทดลองประโยชน์ของข้อมูลเพิ่มเติมด้วยการเปรียบเทียบผลเมื่อใช้และไม่ใช้ข้อมูลนั้น การเก็บข้อมูลอายุไม่ได้หมายความว่าระบบสามารถอนุมานความชอบจากอายุได้ทันที

### 4.3 ระบบแนะนำและการเรียนรู้ของเครื่อง

- สร้างวิธีแนะนำพื้นฐานจากการจับคู่คุณลักษณะเป็นตัวเปรียบเทียบ
- ศึกษาวิธีแนะนำจากเนื้อหา เช่น การแปลงข้อความเป็นเวกเตอร์และการหาสถานที่ที่มีคุณลักษณะใกล้เคียงกับความสนใจ
- เก็บคะแนนความสนใจต่อสถานที่จากผู้ทดลองใช้ เพื่อสร้างตัวอย่างข้อมูลผู้ใช้-สถานที่พร้อมค่าคำตอบสำหรับฝึกโมเดล
- ศึกษา K-Nearest Neighbors Classification ของ scikit-learn และโมเดลแนะนำจากคะแนนใน Surprise โดยเลือกวิธีที่เหมาะกับข้อมูลจากผลทดลอง
- จัดลำดับสถานที่ตามคะแนนที่โมเดลคำนวณ และแสดงรายการแนะนำจำนวนที่เหมาะสมกับหน้าจอ
- รองรับผู้ใช้ใหม่ด้วยข้อมูลความสนใจที่กรอก แม้ยังไม่มีประวัติการใช้งาน
- บันทึกเวอร์ชันข้อมูล การสร้างคุณลักษณะ โมเดล และผลการทดลองเพื่อให้ตรวจสอบและทำซ้ำได้

### 4.4 แอปพลิเคชัน

- พัฒนาแอปพลิเคชันด้วย Flutter สำหรับทดลองใช้งานบน Android
- มีหน้ารับข้อมูลผู้ใช้และความสนใจ หน้ารายการแนะนำ หน้ารายละเอียดสถานที่ และหน้าจัดการข้อมูลผู้ใช้
- มีช่องทางให้ผู้ทดลองใช้ประเมินความสนใจต่อสถานที่
- ใช้รายการแนะนำและแบบฟอร์มความสนใจเป็นช่องทางหลักในการค้นพบสถานที่ โดยไม่มี Search Bar
- ใช้ Firebase สำหรับจัดเก็บข้อมูลและบริการที่จำเป็น และเชื่อมบริการโมเดลผ่าน API
- กำหนดฟังก์ชันสื่อและฟังก์ชันเสริมร่วมกับสถานประกอบการ โดยให้ความสำคัญกับระบบแนะนำและงานทดลอง ML

### 4.5 ขอบเขตที่ยังไม่กำหนด

กำหนดระยะเวลาดำเนินงานรวม 3 เดือน ส่วนจำนวนผู้ทดลองใช้ รายการข้อมูลส่วนบุคคล ฟังก์ชันเสริม และโมเดลสุดท้ายจะกำหนดหลังหารือกับสถานประกอบการและประเมินความพร้อมของข้อมูล โครงการไม่ได้ตั้งสมมติฐานว่ามีข้อมูลผู้ใช้หรือผลประเมินอยู่แล้ว

## 5. แนวทางพัฒนาโมเดล

### 5.1 การเตรียมข้อมูลและสร้างคุณลักษณะ

ตรวจสอบชุดข้อมูลและจัดรูปแบบข้อมูลหมวดหมู่ให้สอดคล้องกัน แยกกิจกรรมที่มีหลายค่า และจัดการค่าว่างตามความเหมาะสม แปลงข้อมูลหมวดหมู่ด้วยวิธีเช่น One-hot Encoding หรือ Multi-hot Encoding และศึกษาการแปลงคำอธิบายสถานที่ด้วย TF-IDF หรือเวกเตอร์ข้อความที่เหมาะกับภาษาไทย

สร้างคุณลักษณะของคู่ผู้ใช้-สถานที่ เช่น ความตรงกันของประเภทสถานที่ กิจกรรม พื้นที่ และความคล้ายคลึงของข้อความ ข้อมูลส่วนบุคคลเพิ่มเติมจะใช้เฉพาะเมื่อมีเหตุผลในการทดลองและมีข้อมูลประเมินประโยชน์ของคุณลักษณะนั้น

### 5.2 การสร้างชุดข้อมูลความสนใจ

ให้ผู้ทดลองใช้ระบุความสนใจและประเมินสถานที่ที่ได้รับชมด้วยคะแนน เช่น ระดับ 1-5 โดยกำหนดความหมายของคะแนนให้ชัดเจน แสดงชื่อ คำอธิบาย และสื่อประกอบอย่างสอดคล้องกัน

วางแผนสุ่มสถานที่ให้ครอบคลุมหลายประเภทและหลายพื้นที่ พร้อมสุ่มลำดับการแสดง เพื่อลดการเก็บคะแนนเฉพาะสถานที่ที่ระบบตั้งต้นแนะนำอยู่แล้ว บันทึกทั้งสถานที่ที่แสดงและคะแนนที่ได้รับ และไม่ถือว่าสถานที่ที่ผู้ใช้ยังไม่ได้ประเมินเป็นสถานที่ที่ไม่ชอบ

ตรวจสอบจำนวนผู้ใช้ จำนวนคู่ข้อมูล การกระจายคะแนน และความครอบคลุมของประเภทสถานที่ก่อนพิจารณาว่าข้อมูลเพียงพอสำหรับฝึกโมเดลหรือไม่

### 5.3 วิธีพื้นฐานและโมเดลที่นำมาเปรียบเทียบ

| วิธี | บทบาทในการทดลอง | ข้อมูลที่ใช้ |
|---|---|---|
| การจับคู่คุณลักษณะตามเกณฑ์ที่กำหนด | วิธีพื้นฐานสำหรับเปรียบเทียบ | ความสนใจและคุณลักษณะสถานที่ |
| การแนะนำจากเนื้อหาและความคล้ายคลึง | วิธีตั้งต้นสำหรับผู้ใช้ใหม่ | คุณลักษณะสถานที่ ข้อความ และความสนใจ |
| K-Nearest Neighbors Classification ด้วย scikit-learn | จำแนกคู่ผู้ใช้-สถานที่ว่าอยู่ในกลุ่มสนใจหรือไม่สนใจ | คุณลักษณะคู่ผู้ใช้-สถานที่และป้ายกำกับที่ได้จากคะแนนความสนใจ |
| โมเดลใน Surprise เช่น SVD หรือ KNNBasic | ทำนายคะแนนความสนใจต่อสถานที่จากรูปแบบคะแนนของผู้ใช้ | รหัสผู้ใช้ รหัสสถานที่ และคะแนนความสนใจ |

**แนวทางที่ 1: K-Nearest Neighbors Classification**

ศึกษาการจำแนกกลุ่มด้วย `KNeighborsClassifier` ตาม[ตัวอย่างของ scikit-learn](https://scikit-learn.org/stable/auto_examples/neighbors/plot_classification.html) โดยประยุกต์ข้อมูลนำเข้าเป็นคุณลักษณะคู่ผู้ใช้-สถานที่ และสร้างป้ายกำกับความสนใจจากคะแนนที่ผู้ทดลองใช้ให้ ตัวอย่างเกณฑ์ที่อาจใช้คือคะแนน 4-5 เป็นกลุ่มสนใจ และคะแนน 1-3 เป็นกลุ่มไม่สนใจ ทั้งนี้ต้องกำหนดความหมายของคะแนนและเกณฑ์ก่อนทดลอง

ปรับสเกลคุณลักษณะตามความเหมาะสม ทดลองจำนวนเพื่อนบ้านและการถ่วงน้ำหนัก และใช้คะแนนความน่าจะเป็นของกลุ่มสนใจเป็นแนวทางจัดลำดับสถานที่ ตัวอย่างต้นทางเป็นการจำแนกดอกไอริส จึงต้องออกแบบข้อมูลและค่าคำตอบสำหรับงานแนะนำสถานที่เพิ่มเติม การใช้ป้ายกำกับประเภทสถานที่เพียงอย่างเดียวไม่ถือเป็นการเรียนรู้ความชอบของผู้ใช้

**แนวทางที่ 2: โมเดลระบบแนะนำด้วย Surprise**

[Surprise](https://surpriselib.com/) เป็นไลบรารี Python สำหรับระบบแนะนำที่ใช้คะแนนซึ่งผู้ใช้ระบุโดยตรง ไม่ใช่ชื่อโมเดลหนึ่งตัว โครงการจะศึกษาโมเดลภายใน เช่น SVD และ KNNBasic เพื่อทำนายคะแนนความสนใจของผู้ใช้ต่อสถานที่แล้วนำมาจัดลำดับรายการแนะนำ

เตรียมข้อมูลในรูปแบบรหัสผู้ใช้ รหัสสถานที่ และคะแนนความสนใจ เช่น ระดับ 1-5 โดยเก็บจากผู้ทดลองใช้จริง ข้อมูลสถานที่เพียงอย่างเดียวไม่เพียงพอสำหรับแนวทางนี้ และไม่ใช้คะแนนที่สร้างจากกฎหรือคะแนนสมมติแทนความชอบจริงในการสรุปคุณภาพของโมเดล

Surprise มาตรฐานไม่รองรับข้อมูลเนื้อหาสถานที่หรืออายุเป็นคุณลักษณะเพิ่มเติมโดยตรง จึงต้องแยกการใช้ข้อมูลเหล่านี้ไว้ในวิธีแนะนำจากเนื้อหาหรือแนวทาง scikit-learn สำหรับผู้ใช้หรือสถานที่ที่ยังไม่มีคะแนน จะใช้วิธีแนะนำจากเนื้อหาเป็นวิธีตั้งต้น

โครงการจะทดลองฝึกและประเมินทั้งสองแนวทางก่อนตัดสินใจ ได้แก่ KNN Classification ด้วย scikit-learn และโมเดลระบบแนะนำใน Surprise โดยเลือกโมเดลภายใน Surprise จากผลการปรับพารามิเตอร์และประเมินบนชุดตรวจสอบ จากนั้นเปรียบเทียบตัวแทนของทั้งสองแนวทางและเลือกใช้เพียงหนึ่งแนวทางเป็นโมเดลหลักของระบบ โดยยังไม่ระบุผู้ชนะก่อนมีผลทดลองจริง วิธีแนะนำจากเนื้อหาใช้รองรับกรณีที่โมเดลหลักยังไม่มีข้อมูลเพียงพอสำหรับผู้ใช้หรือสถานที่นั้น

### 5.4 การฝึกและเลือกโมเดล

แบ่งข้อมูลสำหรับฝึก ปรับพารามิเตอร์ และทดสอบตามสถานการณ์ที่ต้องการประเมิน โดยแยกการทดลองสองกรณี ได้แก่ ผู้ใช้ที่มีคะแนนบางส่วนอยู่ในชุดฝึก และผู้ใช้ใหม่ที่ไม่ปรากฏในชุดฝึก

สำหรับโมเดล Surprise จะประเมินการทำนายคะแนนที่กันไว้ของผู้ใช้และสถานที่ที่มีข้อมูลในชุดฝึก โดยไม่ให้คู่ผู้ใช้-สถานที่เดียวกันซ้ำระหว่างชุดฝึกและทดสอบ ส่วนการประเมินผู้ใช้ใหม่จะแยกกลุ่มตามรหัสผู้ใช้ และรายงานวิธีแนะนำตั้งต้นแยกจากผลของผู้ใช้ที่มีประวัติคะแนน

เรียนรู้ตัวแปลงข้อมูลจากชุดฝึกในแต่ละรอบ ปรับพารามิเตอร์ด้วยข้อมูลฝึกและตรวจสอบ และกันชุดทดสอบไว้ประเมินผลสุดท้าย การเปรียบเทียบการจัดลำดับจะใช้กลุ่มทดสอบและชุดสถานที่ที่มีคะแนนอ้างอิงเดียวกัน

พิจารณา MAE และ RMSE สำหรับการทำนายคะแนน และ Precision กับ F1-score สำหรับการจำแนกความสนใจ ตัวชี้วัดเหล่านี้ตอบคำถามต่างกัน จึงใช้ Precision@K หรือ NDCG@K เพิ่มเติมในการเปรียบเทียบคุณภาพรายการแนะนำ และทดสอบผลของข้อมูลผู้ใช้เพิ่มเติมเฉพาะแนวทางที่รองรับคุณลักษณะดังกล่าว

กำหนดตัวชี้วัดหลักสำหรับเลือกแนวทางก่อนเริ่มทดลอง เช่น NDCG@K โดยกำหนดค่า K และวิธีแปลงคะแนนความสนใจเป็นความเกี่ยวข้องให้เหมือนกันทั้งสองแนวทาง เปรียบเทียบบนผู้ใช้ คู่ข้อมูลทดสอบ และชุดสถานที่สำหรับจัดลำดับเดียวกัน ไม่เปรียบเทียบค่าความแม่นยำในการจำแนกกับ RMSE โดยตรง เลือกแนวทางที่ให้ผลบนชุดตรวจสอบดีกว่าตามเกณฑ์ที่กำหนด แล้วรายงานผลบนชุดทดสอบที่กันไว้ หากผลใกล้เคียงกันให้พิจารณาความสม่ำเสมอของผลแต่ละรอบและเวลาตอบสนองประกอบ

หากปริมาณคะแนนยังไม่เพียงพอ จะจำกัดขอบเขตการทดลองแบบมีผู้สอนตามข้อมูลที่มีและรายงานข้อจำกัดอย่างชัดเจน ระบบแนะนำจากเนื้อหายังใช้เป็นวิธีตั้งต้นได้ แต่จะไม่อ้างผลการเรียนรู้ความชอบของผู้ใช้ที่ยังไม่ได้พิสูจน์

### 5.5 การเชื่อมโมเดลกับระบบ

นำโมเดลที่ผ่านการประเมินมาให้บริการผ่าน API โดยแนวทาง scikit-learn รับข้อมูลความสนใจและคุณลักษณะที่กำหนด ส่วนแนวทาง Surprise ใช้รหัสผู้ใช้และรหัสสถานที่ในการทำนายจากโมเดลที่ฝึกไว้ API ส่งกลับรหัสสถานที่ คะแนนจัดลำดับ และเวอร์ชันโมเดล แอปพลิเคชันดึงรายละเอียดสถานที่จากฐานข้อมูลเพื่อแสดงผล

คำอธิบายการแนะนำจะแสดงข้อเท็จจริงที่ตรวจสอบได้ เช่น กิจกรรมตรงกับที่ผู้ใช้เลือก โดยแยกจากการอ้างเหตุผลภายในโมเดลที่ยังไม่ได้วิเคราะห์

## 9. ผลที่คาดว่าจะได้รับ

1. แอปพลิเคชันต้นแบบที่แนะนำสถานที่ท่องเที่ยวตามข้อมูลความสนใจของผู้ใช้
2. ชุดข้อมูลสถานที่ที่ผ่านการตรวจสอบและชุดคะแนนความสนใจที่จัดเก็บเพื่อการทดลอง
3. กระบวนการฝึกและประเมินโมเดลที่สามารถตรวจสอบและทำซ้ำได้
4. ผลเปรียบเทียบวิธีแนะนำและข้อสรุปที่มีหลักฐานรองรับการเลือกโมเดล
5. รายงานประโยชน์ของข้อมูลผู้ใช้เพิ่มเติม รวมถึงข้อจำกัดเมื่อข้อมูลมีปริมาณน้อย
6. โค้ดระบบ เอกสารการติดตั้ง คู่มือใช้งาน และรายงานสหกิจศึกษา
