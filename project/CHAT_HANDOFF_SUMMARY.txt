KNN / recommendation status:
- KNN V2 notebook exists:
  - notebooks/travel_recommendation_knn_v2_colab.ipynb
- KNN V2 model exists:
  - backend/models/travel_recommendation_knn_model_v2.pkl
- KNN V2 idea:
  - Content-based KNN recommendation.
  - Uses one-hot features for region, province, category, type, activity.
  - Uses TF-IDF text features from description, highlight, tags, nameTh, nameEn.
  - Uses NearestNeighbors(metric="cosine", algorithm="brute") and calls .fit().
  - Exports .pkl containing model, vectorizers/encoders, matrices, metadata, config.
  - Supports optional province by having with-province and without-province paths.
  - Supports exclude_source_rows concept to avoid returning already seen places.
- Important explanation:
  - KNN is lazy learning. Training means fitting/storing feature matrix for nearest-neighbor search, not learning neural-network-like weights.
  - The .pkl is real and usable, but evaluation is not true user-accuracy unless there is real user interaction data or expert labels.

Important KNN audit findings:
1. Multi-select mismatch:
   - Flutter allows multiple regions/provinces/categories/types/activities.
   - Backend currently uses only the first region/province/category/type in request in _build_user_vector.
   - Activities are multi-value.
   - Need fix backend so category/type/region/province multi-select really affects vector.
2. Flutter backend connection:
   - recommendation_repository.dart defaults to http://127.0.0.1:8000.
   - This works for local web preview on same machine, but not real phone.
   - For phone test use LAN IP or hosted backend.
   - Backend README should run uvicorn with --host 0.0.0.0 for LAN testing.
3. Same-input new results:
   - Backend supports exclude_source_rows but Flutter does not send it yet.
   - To avoid showing same places when user searches same preference again, Flutter should send seen sourceRows/history/session exclusions.
4. Result size:
   - Backend may return too many results if no limit.
   - Consider limit/pagination/load more.
5. Evaluation:
   - Current Colab evaluation is based on handcrafted preference cases and relevance rules derived from same features.
   - Good for demonstration, but not true accuracy from real user behavior.
   - For report, describe as offline content-based relevance test, not real user satisfaction accuracy.

Known logic issues to fix soon:
1. Backend KNN multi-select support:
   - Fix backend/main.py so all selected categories/types/regions/provinces contribute to query vector.
2. Flutter should send exclude_source_rows:
   - Use history or session seen list to prevent repeated results for same input.
3. History document ID:
   - history_repository currently risks using duplicated place.id.
   - Should use Firestore documentId or sourceRow instead.
4. sourceRow mapping:
   - recommendation_repository maps sourceRow by index = sourceRow - 1.
   - This works now because sourceRow is sequential, but safer to build Map<int, Place> by sourceRow.
5. Backend deploy:
