ARCHITECTURE AUDIT FOR CLAUDE
TravelRecommendation / Flutter lib/pages review

Purpose
=======

This report follows the architecture principles from Claude:

- pages/ should remain UI layer only.
- data/ should contain repositories and business services.
- models/ should stay as data classes.
- widgets/ should stay reusable UI.
- utils/ should contain generic helpers only, not domain scoring.

This report only audits and recommends. No refactor has been applied yet.

High Priority Refactor Candidates
=================================

1) lib/pages/home_page.dart
---------------------------

Status: definite fat page.

Problems found:

- Business recommendation fallback lives inside the page:
  - _fallbackRecommendation(...) around line 308
  - _scorePlace(...) around line 380
  - _ScoredPlace helper around line 1338

- Search matching and ranking lives inside the page:
  - _displayPlaces(...) around line 283
  - _normalizeSearchText(...) around line 340
  - _matchesSearch(...) around line 344
  - _searchRank(...) around line 348
  - _searchFields(...) around line 359

- Recommendation rotation/key logic lives inside the page:
  - _rotateRecommendationOrder(...) around line 258
  - _recommendationKey(...) around line 271
  - static _recommendationOffsets and _recommendationRotationStep near top of state class

Recommended extraction:

- Create lib/data/local_recommendation_service.dart
  - Move local fallback scoring/filtering into it.
  - Suggested public method:
    LocalRecommendationService.recommendFallback({
      required List<Place> places,
      required RecommendationPreferences preferences,
      required HistoryPreferenceBoost historyBoost,
    })

- Create lib/data/place_search_service.dart
  - Move search normalization, matching, and ranking into it.
  - This is domain search, not generic utils, so data/service layer is better than utils/.
  - Suggested public method:
    PlaceSearchService.search(List<Place> places, String query)

- Create lib/data/recommendation_rotation_service.dart or keep as private service inside local_recommendation_service.dart
  - Move rotation offset/key logic if it remains product behavior.
  - If rotation is purely UI variety, it may remain in HomePage, but currently it is recommendation ordering behavior and should be testable.

Expected HomePage after refactor:

- Loads data from PlaceRepository, HistoryRepository, RecommendationRepository.
- Delegates fallback scoring to LocalRecommendationService.
- Delegates search to PlaceSearchService.
- Keeps only UI state, navigation, and widget build.

Recommended Refactor Order
==========================

Do not refactor everything at once. Suggested order:

1. HomePage recommendation fallback service
   - Create lib/data/local_recommendation_service.dart
   - Move _fallbackRecommendation, _scorePlace, _ScoredPlace
   - Add unit tests for scoring behavior

2. Shared place search service
   - Create lib/data/place_search_service.dart
   - Move HomePage search matching/ranking
   - Reuse it in UploadVideoPage
   - Add fuzzy matching here later

3. Optional recommendation rotation service
   - Move only if the team agrees rotation is recommendation behavior, not UI presentation

4. Auth repository
   - Create lib/data/auth_repository.dart
   - Move email login, Google login, reset password, register
   - Do this after Google Login is tested on device

5. Travel taxonomy
   - Create lib/data/travel_taxonomy.dart
   - Move region/province/category/type/activity lists

6. Shared maps/video UI helpers
   - Extract only if duplication starts slowing changes


Suggested Files To Create
=========================

lib/data/local_recommendation_service.dart
  For fallback scoring/ranking/filtering by preference and history boost.

lib/data/place_search_service.dart
  For place search normalization, fuzzy matching, and ranking.

lib/data/auth_repository.dart
  For FirebaseAuth/GoogleSignIn email login, Google login, register, reset password.

lib/data/travel_taxonomy.dart
  For regions, provinces, categories, types, activities.

lib/utils/maps_launcher.dart
  Optional. For Google Maps URL building/opening shared by Detail, TikTok, MyVideos.


Key Caution
===========

- Google Login was just fixed by updating android/app/google-services.json with oauth_client values from Firebase config.
- Avoid refactoring Google Sign-In logic until it has been tested on a physical device/emulator.
- Do not expose Firebase config files or API keys in handoff files.
- Do not re-enable Places API / Places API (New) unless the user explicitly asks, because it previously caused high billing.


Conclusion
==========

The main architecture problem is real and concentrated in lib/pages/home_page.dart.
The next most useful cleanup is shared place search because both HomePage and
UploadVideoPage implement place matching inside UI state classes.

Recommended first confirmed task:

Refactor HomePage local fallback scoring into:

  lib/data/local_recommendation_service.dart

Then refactor search into:

  lib/data/place_search_service.dart

After that, run:

  flutter analyze
  flutter test
